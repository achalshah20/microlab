# microlab

Training a language model from scratch on free-tier compute — tokenizer, data
pipeline, kernels, training, post-training, inference and RL, built in order,
each milestone gated on a number rather than on the code existing.

**Current status: M0 (end-to-end training loop) implemented; the M0 gate run is
pending a GPU session.**

## What is honest about this repo

- The training loop, checkpointing, resume and data plane are **implemented and
  tested**, including a real preemption test that kills a live process with
  SIGTERM and verifies the run resumes bit-exactly.
- The **M0 gate is not cleared yet.** The gate is 10M params on TinyStories to
  val loss < 1.6, and it needs a GPU session this repo has not had. What has run
  is the same pipeline end to end on a synthetic corpus on CPU.
- The tokenizer is a **placeholder**. It implements byte-level BPE correctly and
  losslessly, in pure Python, at roughly 1/100th of the throughput the real one
  needs. The Rust implementation is M1.
- No number in this README is quoted from anywhere but a run in this repo.

## Quickstart

```bash
pip install -e ".[dev]"

# Build a tokenizer and packed shards from the offline synthetic corpus.
python -m microlab.cli prepare --source synthetic --out-dir data/synthetic \
  --vocab-size 1024 --val-fraction 0.05 --limit 8000

# Train end to end on CPU (~45s).
python -m microlab.cli train m0_cpu

# Sample from the latest checkpoint.
python -m microlab.cli sample m0_cpu --prompt "One day"
```

For the real M0 run, prepare TinyStories instead (needs network) and use the
GPU config:

```bash
python -m microlab.cli prepare --source tinystories --out-dir data/tinystories --vocab-size 8192
python -m microlab.cli train m0
```

Overrides use Hydra dotted syntax anywhere on the command line:

```bash
python -m microlab.cli train m0 optim.lr=3e-4 train.max_steps=2000
```

## Commands

| command | what it does |
| --- | --- |
| `prepare` | corpus → tokenizer → packed `uint16` shards + manifest |
| `train` | train, checkpoint on a wall-clock cadence, resume automatically |
| `sample` | generate from the newest valid checkpoint |
| `bench` | step time, tokens/s, MFU, peak memory, TTFT and decode throughput |
| `shapes` | regenerate [`docs/M0_SHAPES.md`](docs/M0_SHAPES.md) from the live model |

## Design decisions that carry the project

**Preemption is the normal case, not an error.** Every free-tier session dies at
12 hours. Checkpoints are written on a wall-clock cadence with the payload
fsynced before a separate commit marker, so an interrupted write is detectable
rather than merely corrupt; loading walks checkpoints newest-first and falls back
past any that fail. SIGTERM triggers a final flush, and a restarted process
appends to the same run record instead of starting a new one. `tests/test_session_chaining.py`
kills a real training process and asserts the metric history has no gap.

**`(seed, step) → batch` is a pure function.** There is no sampler state to
checkpoint. Sample order is an epoch-wise permutation computed by a keyed Feistel
network — O(1) per index, no materialized shuffle array, exact once-per-epoch
coverage. Resume correctness is a property of the design rather than something to
debug across 50 sessions.

**Precision is a strategy, chosen by one config field.** T4 is Turing: fp16 only,
no bf16, no FlashAttention-2. The fp16 path exposes loss scale and skipped-step
rate as first-class metrics, because a climbing skip rate is visible thousands of
steps before the loss curve moves. Requesting bf16 on a Turing card fails at
startup, not 40 minutes in.

**Correctness is checked against independent references.** `tests/reference.py`
reimplements RMSNorm, RoPE (via complex arithmetic), attention and SwiGLU from
the equations, sharing no code with `src/`. RoPE is additionally checked for its
defining relative-position property, and cached decoding is checked against full
recomputation — the bug class that produces fluent, wrong output rather than a
crash.

**The MFU denominator is tested.** `docs/M0_SHAPES.md` is generated by walking
the live model with forward hooks; a test asserts that per-module sum agrees with
the closed-form `flops_per_token` to within 2%. It did not, at first: the formula
omitted the tied LM head and would have inflated every reported MFU by 16%.

## Testing

```bash
pytest -m "not slow"   # fast correctness suite
pytest                 # everything, including the SIGTERM preemption tests
pytest -m gpu          # GPU-only tests (run these on Kaggle)
```

CI is CPU-only and runs lint, both test tiers, and the documented quickstart from
a clean checkout.

## Layout

```
src/microlab/
  config.py         typed schema (dataclasses + OmegaConf structured configs)
  precision.py      fp16 / bf16 / fp32 strategies
  bench.py          throughput, memory, MFU, decode latency
  shapes.py         forward-pass shape and FLOP instrumentation
  model/            RMSNorm, RoPE, GQA attention on SDPA, SwiGLU, Transformer
  data/             packing, manifests, Feistel permutation, deterministic batching
  tokenizer/        byte-level BPE (placeholder; Rust lands in M1)
  train/            trainer, optimizer/schedules, durable checkpointing
  utils/            determinism, run record, hardware peak-FLOPs table
configs/            m0 (T4 gate), m0_cpu (offline integration)
tests/              correctness suite + independent reference implementations
```
